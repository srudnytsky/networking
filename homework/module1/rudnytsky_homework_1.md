## Завдання 1. Перегляд мережевих інтерфейсів

**Команда:**

```bash
ip a
```

**Вивід**

```text
srudnytsky@Trinity:~/networking/networking$ ip a
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN group default qlen 1000
    link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
    inet 127.0.0.1/8 scope host lo
       valid_lft forever preferred_lft forever
    inet 10.255.255.254/32 brd 10.255.255.254 scope global lo
       valid_lft forever preferred_lft forever
    inet6 ::1/128 scope host
       valid_lft forever preferred_lft forever
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc mq state UP group default qlen 1000
    link/ether 00:15:5d:6b:86:a4 brd ff:ff:ff:ff:ff:ff
    inet 172.25.51.69/20 brd 172.25.63.255 scope global eth0
       valid_lft forever preferred_lft forever
    inet6 fe80::215:5dff:fe6b:86a4/64 scope link
       valid_lft forever preferred_lft forever
```

Основні параметри інтерфейсу `eth0`:

- **Тип підключення:** Ethernet.
- **MAC-адреса:** `00:15:5d:6b:86:a4`.
- **Локальна IPv4-адреса:** `172.25.51.69`.
- **Маска підмережі:** `255.255.240.0`.
- **Префікс:** `/20`.
- **Адреса мережі:** `172.25.48.0`.
- **Broadcast-адреса:** `172.25.63.255`.
- **Шлюз за замовчуванням:** `172.25.48.1`.
- **Кількість доступних адрес хостів:** `4094`.

IPv4-адреса та маска підмережі належать до третього рівня моделі OSI — мережевого. MAC-адреса належить до другого рівня — канального.

Маска `/20` залишає 12 біт для адресації хостів. Загальна кількість доступних адрес становить `2^12 - 2 = 4094`.

## Завдання 2. Аналіз таблиці маршрутизації

**Команда:**

```bash
ip r
```

Результат виконання:

```text
srudnytsky@Trinity:~/networking/networking$ ip r
default via 172.25.48.1 dev eth0 proto kernel
172.25.48.0/20 dev eth0 proto kernel scope link src 172.25.51.69
```

Перший запис визначає маршрут за замовчуванням. Пакети до мереж, для яких немає конкретнішого маршруту, передаються через шлюз `172.25.48.1` за допомогою інтерфейсу `eth0`.

Другий запис описує безпосередньо підключену мережу `172.25.48.0/20`. Параметр `scope link` означає, що мережа доступна через цей інтерфейс без додаткового шлюзу, а `src 172.25.51.69` вказує на IP-адресу джерела.

Параметр `proto kernel` характеризує походження запису маршрутизації, але не підтверджує отримання IP-адреси через DHCP. Для визначення способу призначення адреси необхідно перевірити додаткову конфігурацію мережі.

## Завдання 3. Визначення публічної IP-адреси

**Команда:**

```bash
curl ifconfig.io
```

Результат:

```text
188.163.8.75
```

Сервіс `ifconfig.io` визначив публічну IP-адресу підключення як `188.163.8.75`.

Локальна адреса `172.25.51.69` належить до приватного діапазону IPv4-адрес `172.16.0.0/12` і використовується у внутрішній мережі WSL. Публічна адреса `188.163.8.75` видима зовнішньому сервісу під час виконання запиту.

Різниця між цими адресами узгоджується з використанням NAT (Network Address Translation) або іншого механізму трансляції чи проксіювання трафіку. NAT дає змогу пристроям із приватними адресами обмінюватися даними з Інтернетом через публічну адресу. За результатами цієї роботи неможливо точно визначити, на якому саме рівні мережевої інфраструктури виконується трансляція.

## Висновок

Під час роботи було досліджено мережеві параметри Linux у середовищі WSL. Визначено параметри мережевого інтерфейсу `eth0`, локальну IP-адресу, маску підмережі, адресу мережі, широкомовну адресу та шлюз за замовчуванням.

Аналіз таблиці маршрутизації дав змогу зрозуміти, як система визначає шлях передавання пакетів. За допомогою `curl ifconfig.io` було визначено публічну IP-адресу підключення. Також розглянуто різницю між приватними та публічними IP-адресами й роль NAT у забезпеченні мережевого обміну.

Окремо встановлено, що параметр `proto kernel` не дозволяє зробити висновок про використання DHCP без додаткової перевірки конфігурації системи.
